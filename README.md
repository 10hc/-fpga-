# 基于安路 EG4S20 的音视频融合多媒体展示系统

全国大学生嵌入式芯片与系统设计竞赛 · FPGA 创新设计赛道 · 选题一

以单片安路 **EG4S20BG256** FPGA 为核心，构建一个**不需要外部处理器、也不依赖上位机在线参与**的本地多媒体展示终端：
从 FAT32 格式的 TF 卡读取素材，在片内完成图像解析、缩放、SDRAM 帧缓存调度、转场、字幕与音频输出，
最终经 HDMI 1.4b 输出 640×480@59.52 Hz 彩色画面与双声道 PCM 音频。整机控制与数据处理全部由 Verilog RTL 实现。

---

## 一、功能一览

| 功能 | 说明 | 主要模块 |
|---|---|---|
| TF 卡自动识别 | 根目录扫描 FAT32，按扩展名（`.BMP` / `.WAV` / `.VID`）定位文件，无需固定文件名 | `fat32_scan.v` |
| BMP 图片显示 | 24 位非压缩 BMP，宽高 1~2048；等比缩放 + 黑边填充到 640×480 | `bmp_read.v`、`bmp_scale.v` |
| 图片切换与轮播 | KEY2 短按切下一张；KEY4 开/关自动轮播（1 秒一张） | `top_tf_hdmi_audio.v` |
| 花样转场 | 每次切图轮换 **滑动 → 栅格 → 淡入淡出**；在读地址层面对比新旧缓冲，单读端口即可实现 | `image_transition_ctrl`（顶层内嵌） |
| 视频播放 | 长按 KEY2 进出视频模式；VID1/VID2 容器逐帧解包，320×240 RGB565 放大 2 倍至 640×480，四缓冲轮转 | `video_player.v` |
| 背景音乐 | 图片模式循环播放 TF 卡 WAV（48 kHz / 16 bit / 立体声）；找不到文件时用板内 ROM 旋律兜底 | `wav_audio.v` |
| OSD 与诊断 | 底部滚动字幕、亮度/对比度档位提示、左上 8 格方块实时显示内部状态 | `osd_overlay.v` |
| 参数调节 | KEY3 短按循环亮度（4 档），长按 1 s 循环对比度（4 档） | `video_adjust.v`、`key_short_long.v` |
| 异常自恢复 | 扇区总线看门狗、超时强拆并补发结束事件、模式切换排空、完整帧提交 | `sd_card_bmp.v`、`frame_fifo_*.v` |

> **音频现状**：图片模式有声（WAV 背景音乐）；视频模式当前**静音**（VID1 容器不含音轨）。
> VID2（画面与音轨打包进同一个 `.VID`）的 RTL 与仿真已并入仓库（`av_pcm_player.v`、`make_av_video.py`），
> 尚未接入顶层，属下一步工作，详见 `lab_ex5_i2s/docs/音视频打包与同步播放.md`。

## 二、硬件平台与关键指标

| 项目 | 参数 |
|---|---|
| 主控器件 | 安路科技 EG4S20BG256（19 600 LUT / 64×BRAM9K / 29 DSP / 4 PLL） |
| 开发板 | HX4S20C（50 MHz 有源晶振、SiP SDRAM 2 M×32 bit、HDMI_B 接口） |
| 存储 | TF 卡，FAT32，SPI 模式 25 MHz，512 B/扇区 |
| 帧缓存 | 片内 SDRAM 8 MB，划分 4 个 640×480 帧区（单帧 1.17 MB） |
| 显示 | HDMI 1.4b，640×480@59.52 Hz，RGB888，像素时钟 25 MHz，TMDS 5×125 MHz |
| 音频 | I2S 64fs，主时钟约 12.288 MHz，48 kHz / 16 bit / 立体声 |

最近一次布局布线（工程 `HDMI1.4b_Transmitter_fixed`，2026-10-31）：

| 资源 | 已用 / 总量 | 占用率 |
|---|---|---|
| LUT | 12 810 / 19 600 | 65.4 % |
| BRAM9K | 64 / 64 | **100 %** |
| DSP | 7 / 29 | 24.1 % |
| PLL | 3 / 4 | 75.0 % |

时序：全局 SWNS −6.699 ns / STNS −370.161 ns，62 个违例端点。
其中 −6.699 ns 来自 SDRAM 读出采样组（厂商加密 IP 的板级相位建模，原例程同样存在，不影响功能）；
属于本项目可修范围的是 SD 处理域的组合路径（最差约 −1.1 ns），后续用“高位比较 + 低位屏蔽”拆分超时计数器即可收敛。
**BRAM 已经用满**，后续加行缓冲类功能需要先腾出空间。

## 三、系统组成

```
TF 卡 ──SPI── 扇区控制器 ──┬─ 目录解析（开机一次）
                          ├─ BMP 解析 + 缩放 ─┐
                          ├─ VID 解析 + 放大 ─┼─ 帧写 ─ SDRAM 帧区 ─ 帧读 ─ 显示合成 ─ OSD ─ HDMI
                          └─ WAV 解析 ────────┘                                  └─ I2S 音频包
```

- **五个时钟域**：SD 处理域 100 MHz、视频域 25 MHz、像素位时钟 125 MHz、音频主时钟 12.288 MHz、HDMI 5×125 MHz。
- **三条媒体流共享一条 SPI 扇区总线**：仲裁器采用“授权即锁定 + 配额轮转 + 看门狗强拆”，
  一次扇区事务不会被拆成两半；异常访问超时后强制收尾，不会把整机拖死。
- **四类跨时钟域**：翻转握手（帧完成事件）、多级同步（缓冲索引、诊断字）、异步 FIFO（帧数据）、四相握手（音频样本）。
- **完整帧提交**：一帧只有源结束且写通道报告写完后才发布给显示侧，切换索引发生在帧边界，因此不会撕裂。

模块划分、数据通路与握手约定详见 `lab_ex5_i2s/doc/设计说明_运行框架与优化建议.md`。

## 五、素材准备

| 素材 | 要求 | 工具 |
|---|---|---|
| 图片 | BMP，24 位非压缩，宽高 1~2048（建议 640×480），放卡根目录 | `lab_ex5_i2s/doc/convert/convert_images_to_bmp.py` |
| 视频 | VID1（无音轨，工具默认 25 fps）或 VID2（含音轨，建议 12 fps），320×240 RGB565 | `make_video.py`、`make_av_video.py` |
| 音频 | WAV，PCM，48 kHz / 16 bit / 立体声 | 任意音频软件 / FFmpeg |

说明：读取器沿**物理连续扇区**顺序读，不遍历簇链，因此素材需连续存放；
卡根目录只保留一个 `.WAV` 和一个待播放的 `.VID`（扫描器只取遇到的第一个）。

## 六、编译与下载

1. 用 **Anlogic TD 6.2.1** 打开 `lab_ex5_i2s/src/td_project/HDMI1.4b_Transmitter_fixed.al`；
2. 点 **全编译**（综合 → 布局布线 → 生成比特流）。改完源码必须全编译，只跑布局布线会复用旧网表；
3. 位流位于 `..._Runs/phy_1/HDMI1.4b_Transmitter_fixed.bit`，用 TD 下载；
4. HDMI 线插开发板 **HDMI_B** 口。

> 新增源文件时先在 TD 里 `Project → Add/Remove Files` 加入，或**关闭 TD 后**再改 `.al`（TD 退出时会覆盖 `.al`）。
> 若改动被 `import/` 副本引用的文件（如 `wav_audio.v`），需同步副本；`lab_ex5_i2s/doc/tools/prebuild_check.ps1` 会自动检查。

## 七、仿真

`lab_ex5_i2s/src/user_source/hdl_source/test/` 提供 ModelSim 脚本，覆盖栅格转场逐地址（4300 万次像素地址）、


## 八、按键与诊断

| 按键 | 引脚 | 功能 |
|---|---|---|
| KEY_2 | B2 | **短按**：切换下一张图片；**长按 1.5 s**：进入/退出视频模式 |
| KEY_4 | C1 | 自动轮播 开 / 关 |
| KEY_3 | B1 | **短按**：亮度循环；**长按 1 s**：对比度循环 |

屏幕左上角 8 个方格为诊断指示（红=1，绿=0），可实时读出播放器状态码、写请求、取数与出像素状态，
没有逻辑分析仪时也能定位到具体模块。

## 九、已知限制

- BRAM 已 100 % 占用，双线性缩放、行缓冲类功能需要先做资源置换；
- SD 处理域仍有约 −1.1 ns 组合路径违例，尚未收敛；
- SPI 有效载荷上限约 2.78 MB/s，高帧率视频需先解决带宽（VID1 默认 25 fps 是在无音频、低码率前提下定型的）；
- 只支持物理连续存放的素材，碎片卡需整理或改用簇链遍历；
- 视频模式暂无声音（VID2 音轨待接入顶层）。
