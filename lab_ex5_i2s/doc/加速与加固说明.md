# ★★★ 三项提速与加固（2026-10-26）

对应 `doc/设计说明_运行框架与优化建议.md` 里 ★★★ 三条的落地实现。

## 一、FAT32 目录一次性解析：文件直接定位，不再逐扇区扫描

**问题**：原来找 `.VID`（和开机找 BMP）都是"从扇区 0 开始一个扇区一个扇区读，比对文件头"。
仓库里那个 `VIDEO.VID` 的首扇区是 39392，按实测 ≈1ms/扇区，**光找到文件就要 40 秒以上**，
最坏要扫到 131071 扇区（≈2 分钟）—— 长按 KEY2 后一直是蓝屏就是这个原因。

**做法**：

| 文件 | 改动 |
|---|---|
| `src/user_source/hdl_source/SD/fat32_scan.v` | 新增（从归档工程取回并按本工程扩展）：读 MBR → 找 FAT32 分区 → 解析 BPB → 走根目录簇 → 读目录项，一次拿到 `.BMP`（最多 4 张）、`.WAV`、`.VID` 的首扇区；支持 8.3 大写/小写扩展名 |
| `SD/sd_card_bmp.v` | 例化 `u_fat32_scan`；扇区总线从两级复用改为**三级**（目录解析 > 图像 > 音频/视频）；解析结果经 `locate_done/locate_error/vid_file_*/wav_file_*` 输出 |
| `SD/bmp_read.v` | 新增"跳转模式"：`jump_en=1` 时直接从目录给出的扇区读 BMP 头，不再从 0 扫 |
| `video_player.v` | 新增 `file_valid`/`file_sector`：`addr <= file_valid ? file_sector : SCAN_START`，只容忍文件首扇区后 3 个扇区 |
| `wav_audio.v` | 同上，直接跳到 `.WAV` 首扇区找 RIFF |
| `top_tf_hdmi_audio.v` | 把上面这些新端口接起来 |

**兜底**：`sd_card_bmp.v` 里加了 3 秒解析超时（`LOCATE_TO_CYCLES`）——万一遇到异常卡解析卡住，
3 秒后仍然退回原来的暴力扫描，保证"至少还能看图"，不会因为解析失败导致整机无图。

## 二、WAV 环形缓冲 512 → 4096 样本

**问题**：原来缓冲只有 512 个样本 = **10.7ms**。图像一次连续占用总线（读一整张图 921KB ≈ 0.3 秒）时，
音频缓冲早就读空 → 断音/噪音。另外原来的满阈值是 384，一个扇区最多加 128 个样本，
计数会正好停在 512 = `wrp==rdp`，被当成"空"，读写指针永久错位 → 持续噪音。

**做法**（`src/user_source/hdl_source/wav_audio.v`）：
- `reg [31:0] sbuf [0:4095];`、`wrp/rdp/buf_cnt` 全部 9 位 → 12 位；
- 满阈值 `buf_room = (buf_cnt <= 12'd3967)`（4095 = 4096-1 是"满"，必须留一格）；
- 4096 样本 = **85ms @48kHz**，配合"只在扇区边界让路"，图像连续读图时音乐不会再干涸。

## 三、SD 卡初始化加固

**问题**：`sd_card_sec_read_write.v` 里任何一条命令（CMD0/CMD8/CMD55/CMD41/CMD16）只要没有响应，
状态机就**永久停在那一步**，`sd_init_done` 一直是 0 —— 表现就是红屏（`state_code=0`），
只能按复位；卡稍微接触不良就整机瘫痪。

**做法**：
- 上电后先等 `POR_CYCLES = 10ms` 再发 CMD0（卡上电稳定 + ≥74 个时钟的规范要求）；
- `init_wd` 看门狗：2 秒内 `sd_init_done` 没拉高就**强制回 `S_IDLE` 重新初始化**，
  并且每 2 秒自动重试一次，插卡/接触问题恢复后能自己起来。
