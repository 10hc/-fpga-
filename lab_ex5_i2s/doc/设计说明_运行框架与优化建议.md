> 功能：TF 卡 BMP 图片轮播（切图 + 花样转场 + OSD 字幕）、TF 卡 WAV 音乐、TF 卡 .VID 视频播放、HDMI 音视频同步输出

## 1. 系统概述

整块板子只做一件事：**把 TF 卡里的媒体文件，经过 FPGA，变成 HDMI 上的画面和声音**。

系统里有三条互相独立、但**抢同一个 TF 卡**的数据流：

| 数据流 | 源 | 目标 | 带宽 |
|---|---|---|---|
| 图像 | TF 卡 BMP（640×480 24bit） | SDRAM → 屏幕 | 加载时 ≈ 4 MB/s |
| 视频 | TF 卡 .VID（320×240 RGB565） | SDRAM → 屏幕 | 播放时 ≈ 3.9 MB/s |
| 音频 | TF 卡 WAV（48kHz 16bit 立体声） | HDMI 音频通道 | ≈ 0.19 MB/s |

TF 卡走 SPI（25 MHz），实测 ≈ **1.0 ms/扇区 ≈ 4 MB/s**。这就是整个系统的**总带宽**，也是所有设计取舍的根源：**三条流必须分时复用 SD 总线**。

## 3. 时钟域与复位

| 时钟 | 频率 | 来源 | 主要负载 | LUT |
|---|---|---|---|---|
| `sd_card_clk` | 100 MHz | sys_pll clk0 | sd_card_bmp、bmp_read、wav_audio、video_player、写时钟 | 1950 |
| `ext_mem_clk` | 100 MHz | sys_pll clk1 | frame_read_write、frame_fifo_read/write、trans_ctrl | 488 |
| `ext_mem_clk_sft` | 移相 100 MHz | sys_pll clk2 | SDRAM IP 内部采样（PAD 时序用） | — |
| `video_clk` | 25 MHz | video_pll clk0 | 视频时序、OSD、video_adjust、按键、数码管 | 1390 |
| `hdmi_5x_clk` | 125 MHz | video_pll clk1 | LVDS 10:1 串化（TMDS 位时钟） | 33 |
| `audio_mclk` | 12.288 MHz | PLL_HDMI_AUDIO clk2 | I2S 主时钟（64fs） | 48 |

**复位**：只有外部 `rst_n`（KEY_1）与 `startup_pulse`（上电单脉冲，触发一次 EDID 读取），**没有软复位/看门狗复位**。

**跨时钟域（CDC）现状**（全部手写，共 4 处）：

| 信号 | 方向 | 方式 |
|---|---|---|
| `frame_write_toggle_mem` | ext_mem_clk → sd_card_clk | 先在自己域打拍转 toggle，再两级同步 + 边沿检测 |
| `disp_buf_idx` | sd_card_clk → ext_mem_clk | `disp_sync0/1/2` 三级打拍 |
| `key_dbg` | sd_card_clk → video_clk | `key_dbg_v1/v2` 两级打拍（10/25 补，消除 -4.252ns） |
| 音频 L/R 采样 | sd_card_clk → video_clk | `aud_valid/aud_left/aud_right` + ack 四相握手 |

## 4. 三条数据通路

### 4.1 图像通路（BMP）

```
TF 卡 ──SPI──> sd_card_sec_read_write ──> bmp_read ──> (写请求/数据)
                     ↑ 扫描/加载请求            │
                 扇区仲裁器 ←───────────────────┘
                     │
        frame_fifo_write ──> SDRAM 写口 ──> SDRAM(BUF0/BUF1)
                     ↑
        frame_fifo_read  <── SDRAM 读口 <── frame_read_write
                     │
             video_delay ──> video_adjust ──> osd_overlay ──> video_rgb_to_axis ──> HDMI
```

- `bmp_read` 负责：**逐扇区扫描**（找 `BM` 签名）→ 校验 640×480/24bit/无压缩 → 流式输出像素 → 回到 idle。
- 双缓冲：`BUF0_ADDR = 0`、`BUF1_ADDR = 307200`（字），一屏 307200 字 = 1.17 MB。
- 提交（commit）：只有 **源数据送完（`source_done_seen`）+ 写 FSM 结束（`write_done_seen`）** 同时成立，才切换 `disp_buf_idx` 并点亮 `display_valid`——这是 10/25 修掉"切图后花屏"的关键。
- 写路径开着 `WRITE_V_FLIP`（BMP 是自下而上存的，写进 SDRAM 时翻正）。
- 2 s 看门狗：加载超时则强制结束，避免卡死。

### 4.2 视频通路（.VID）

```
TF 卡 ──SPI──> video_player ──(写请求/数据)──> frame_fifo_write ──> SDRAM 写口
                    │ 扫描 "VID1" → 读头 → 逐组搬 4 行
                    └─ 输出 display_valid / 缓冲区选择
```

- 格式：512B 头（`VID1` + 宽/高/帧率/帧数）+ 每帧 300 扇区（320×240 RGB565，无压缩）。
- 每 5 个扇区（2560B = 1280 像素 = 正好 4 源行）为一组，1 字/2 拍输出，60 组 = 1 帧。
- 显示侧 2 倍放大到 640×480（同一像素输出两次、同一行发两次）。
- KEY2 长按 1.5 s 进入视频模式；进入后图像的按键被屏蔽、音频被停掉（`enable = display_valid & ~video_mode`）。

### 4.3 音频通路（WAV）

```
TF 卡 ──SPI──> 扇区仲裁器 ──> wav_audio(512×32 环形缓冲) ──12.288MHz/48kHz──> 
              I2S_receiver ──> audio_arc_calculate(ACR) ──> HDMI 音频包
```

- WAV 必须是 **48 kHz / 16 bit / 立体声 PCM**（ACR 的 N=6144 是按 48 kHz 算的）。
- 环形缓冲 512 个 32bit 样本 = 10.7 ms；写入阈值 383（永不写满，避开"满=空"歧义）。
- `enable` 拉低时在**扇区边界**停（字节不对齐会毁掉一个扇区）。
- 没有 WAV 或未使能时，输出内部测试音（`hdmi_audio_tone_i2s_64fs`）。

### 4.4 SD 扇区仲裁（三条流的调度器）

```
bmp_read 请求 ──┐
video_player ───┼──> 仲裁器（配额轮转：图像连续 2 次后给音频 1 次）
wav_audio ──────┘        │
                     sd_card_sec_read_write（一次事务：请求 → 512B → end）
```
- 规则：**授权即锁定**，一个扇区事务内不切换，避免撕裂。
- 图像优先级更高（人眼对切图卡顿敏感，音频靠缓冲吸收）。

## 5. 控制与诊断通路

| 输入 | 功能 |
|---|---|
| KEY_1 (A2) | 全局复位 |
| KEY_2 (B2) | 短按：切下一张图；长按 >1.5 s：进/出视频模式 |
| KEY_4 (C1) | 短按：切下一张图；自动轮播开关 |
| KEY_3 (B1) | 短按：亮度；长按 >1 s：对比度 |

**上板诊断系统**（这是本项目最实用的部分）：

- **屏幕底色** = `state_code`：🔴红=SD 未初始化 ｜ 🟢绿=就绪/无图 ｜ 🔵蓝=扫描中 ｜ 🟣紫=加载中 ｜ 🩵青=收像素 ｜ 深蓝=视频模式
- **左上 8 个方块**：`[sd_init_done, display_valid, load_busy, wd_seen, short_load, state_code[2:0]]`；视频模式下是交替图案（绝不会和图像模式混淆）
- **数码管**：显示 `state_code`

> 判读方法：任何异常先拍照，看底色 + 方块即可定位到"卡没初始化 / 没找到图 / 加载中断 / 提交失败 / 视频未出图"。

## 7. 设计检查：不合理 / 有风险的地方

### 🔴 严重（建议优先处理）

**7.1 FAT32 文件定位靠"逐扇区暴力扫描"——最大的设计缺陷**
- 现状：`bmp_read` 从扇区 0 开始逐扇区找 `BM`；`video_player` 逐扇区找 `VID1`，扫描上限 131071 扇区。
- 代价：① 视频文件在 19 MB 处 → **每次进视频模式要等 40~50 秒**；② 最坏情况 131 s；③ 每进一次模式都要重扫，没有缓存。
- 这是"卡反应慢"的**唯一原因**，也是体验上最扎眼的问题。
- 正确做法：读 MBR → 分区起始 LBA → BPB → **根目录项里直接拿文件首簇**，一次定位 < 1 s。（扩展版工程里已经有 `fat32_scan.v` 做过这件事，可以直接移植。）

**7.2 SD 卡初始化失败后没有任何补救**
- 现状：上电只初始化一次；失败就一直重试同一条命令，屏幕永远红色（10/26 你遇到的红屏就是这个）。
- 加固方案：① 上电先发 ≥74 个时钟（CS 高）+ 至少 1 ms 延时；② 初始化失败 N 次后**降低 SPI 时钟**重试；③ 加"卡片拔出/重新插入"检测（CMD13 或重新发 CMD0）。

**7.3 WAV 缓冲太小（512 样本 = 10.7 ms）**
- 图像连续占 2 个扇区配额时，音频只有 1 个扇区的时间补充；一旦 SD 事务延迟抖动，缓冲就见底 → 噪音。
- 建议放大到 4096 样本（16 KB = 8 个 BRAM9K，BRAM 还富余 43 个），缓冲 85 ms，噪音基本可以根除。

### 🟠 中等（结构性，影响可维护性/时序）

**7.4 `sd_card_bmp.v` 职责过多**：扫描调度 + 加载 + 双缓冲 + 提交 + 看门狗 + 按键 + 扇区仲裁 + 音频让路，全在一个模块里。建议拆分：`scan_ctrl` / `load_ctrl` / `sector_arbiter`。

**7.5 顶层是"上帝模块"**（770+ 行）：PLL、按键、OSD、转场、两个播放器、音频、HDMI、数码管全在里面。建议拆出 `video_pipeline.v`、`audio_subsys.v`、`ctrl_subsys.v`。

**7.6 跨时钟域全靠手写**（4 处两/三级同步器 + 1 处 toggle 握手）。建议统一成一个 `cdc_sync.v` / `cdc_toggle.v`，避免以后再漏。

**7.7 `bmp_read.ready = (state == ST_IDLE)` 语义反直觉**（是"可接收"，不是"已完成"）。这个命名直接导致过"加载第一拍就置起 source_done"的故障。建议改名 `idle`，并**新增 `load_done` 输出**。

**7.8 OSD 组合链超预算**：−4.305 ns（8 条路径）。建议在字形选择后加一级流水，代价是字幕延迟 1 像素。

**7.9 诊断逻辑混在显示通路里**：`assign vout_data = display_valid ? vout_data_raw : diag_color;` 把诊断色组合进像素输出。建议改成寄存器选择，或干脆做成"诊断模式时整屏替换"。

**7.10 常量散落**：640/480、320/240、307200、131071、25_000_000 等魔数散在 8 个文件里。建议集中到 `include/project_config.vh`。

### 🟡 轻微（体验/规范）

**7.11 短按在"松手"时才响应**（`key_short_long` 用 `stable && !stable_d`）。切图要等手指抬起来，且早期出现过"长按误判成长短双触发"。建议改成按下沿立即发短按脉冲，长按仍按时间判定，二者互斥。

**7.12 `.al` 里有两个文件是从 `td_project/import/` 副本编译的**（`key_short_long.v`、`wav_audio.v`）——这是 TD 自动复制的，**改源文件不会生效**，极易踩坑。要么在 TD 里改回直接引用，要么每次综合前用 `doc/tools/prebuild_check.ps1` 校验副本一致性（脚本已经有了）。

**7.13 数码管只显示 `state_code`**，信息量太低。建议显示：当前图片序号 / 播放帧率 / 音量 / 错误码。

**7.14 按键功能不直观**：KEY_2 与 KEY_4 短按都是"下一张"，长按分别是"视频模式"和"轮播开关"，没有任何屏幕提示。建议 OSD 上显示一行操作提示或状态。

**7.15 没有性能计数器**：看不到实时帧率、SD 利用率、缓冲水位。建议加一个 OSD 调试页。

## 8. 优化建议（按性价比排序）

| 优先级 | 优化项 | 预期收益 | 工作量/风险 |
|---|---|---|---|
| ★★★ | 用 FAT32 目录解析替代暴力扫描（7.1） | 文件定位 40~50 s → **<1 s** | 中（移植 `fat32_scan.v`），低风险 |
| ★★★ | WAV 缓冲 512 → 4096（7.3） | 消除音乐噪音 | 小，低风险 |
| ★★★ | SD 初始化加固（7.2） | 消除"红屏打不开" | 小，低风险 |
| ★★☆ | 多图预载进 SDRAM | 切图 335 ms → **瞬时**；SDRAM 32 MB 现在只用了 2.4 MB | 中 |
| ★★☆ | 视频用 RGB332（1 B/像素） | 视频带宽减半 → 25 fps 提到 ~45 fps，或换 640×480@12 fps | 中（PC 端 + FPGA 端同时改） |
| ★★☆ | `spi_master` 提速 25 → 50 MHz | 图片加载 335 → ~170 ms，视频帧率翻倍 | 中（例程 IP 改动，需上板验证信号完整性） |
| ★★☆ | OSD 加流水（7.8） | 清掉 −4.3 ns，字幕路径更稳 | 小 |
| ★☆☆ | 转场特效扩展 | 百叶窗、马赛克渐隐、缩放转场（答辩加分） | 中 |
| ★☆☆ | 数码管显示有用信息（7.13） | 演示更专业 | 小 |
| ★☆☆ | VGA 同步输出（引脚已约束在 pin.adc 里） | 双屏显示，演示亮点 | 中 |
| ★☆☆ | 视频模式复用同一份扫描结果 | 二次进入视频模式不再等 40 s | 小（配合 7.1 后自动解决） |
| ★☆☆ | UART 控制 / OV5640 摄像头 | 拓展方向 | 大 |

## 9. 上板快速诊断清单

| 现象 | 处方 |
|---|---|
| 整屏红 | `state_code=0`：SD 卡没初始化 → 断电重插卡；仍失败则做 7.2 加固 |
| 整屏绿 | 卡正常但没找到图片 → 检查 BMP 是否 640×480/24bit/无压缩、是否在 64 MB 扫描窗口内 |
| 整屏蓝（长时间） | 正在扫描：图片多/文件靠后时正常，超过 2 分钟说明文件在扫描窗之外 |
| 整屏深蓝 | 视频模式：正在扫描 `VID1`，正常要等 40~50 s（做了 7.1 后是秒级） |
| 方块1 绿 | `sd_init_done=0` → 就是上面的红屏 |
| 方块2 红 | `display_valid=1` → 已有图在显示 |
| 方块3 红（常亮） | `load_busy=1` → 加载卡住，等 2 s 看门狗释放 |
| 切图后花屏 | 提交条件被破坏（源未送完或写未结束就提交），查 `source_done_seen` / `write_done_seen` |
| 音乐变噪音 | 优先查 WAV 缓冲水位与扇区仲裁配额（7.3） |
